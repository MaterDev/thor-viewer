# Live Page Mode: risks and mitigations

Readiness review for making Live the viewer's default (2026-09-19). "Done" = in code and tested;
"open" = a known gap with the proposed shape.

| # | Risk | What happens | Mitigation | Status |
|---|---|---|---|---|
| 1 | adb / Wireless debugging off after a reboot or Wi-Fi change | No CDP endpoint, so Live cannot attach. | `/api/live/start` tries `thor-adb connect` (finds the new port itself). If that fails the server leaves Live (headless resumed) and the viewer falls back to Stream with a notice; Key's choice stays "live", so the next open tries again. Re-enabling Wireless debugging stays a manual step. | done (e2e: "Live cannot start -> Stream") |
| 2 | CDP forward lost mid-session | The bridge's socket closes. | `viewerGone` emits `fallback`, leaves Live, and the viewer switches to Stream with a notice. Paused pages resume because Chrome releases a debugger pause when the pausing connection dies. | done (e2e: proxy cut) |
| 3 | Viewer app backgrounded or reloaded | Reload: a new document; background: Android may discard the page. | A main-frame navigation of the viewer target ends Live at once; dead event streams are pruned by a 15 s ping, then Live is left after a 3 s grace. On return the page re-enters Live from its saved choice. | done (e2e: navigate away) |
| 4 | Server restart while Live or borrowed | The server's CDP connections drop. | Chrome releases both pauses when their connections close (measured: headless back at 62 fps). On startup the server thaws a headless page left by a crash (`recoverAtStartup`). The viewer's event stream reconnects and the page re-POSTs `start`, so it re-attaches. | done (unit + e2e crash check; the reconnect path is client code, not yet covered end to end) |
| 5 | Agents act while Key is in Live without the gate | Their commands go to the paused headless page and hang until agent-browser times out (measured: still hanging at 10 s). | The gate is now installed. `LIVE_PAUSE_HEADLESS=auto`: the headless page is paused only while the gate is the installed wrapper, so uninstalling the gate turns this into "headless keeps running" rather than "commands hang". Callers that always mean the headless page (tests, start.sh, the server) set `THOR_GATE=off`. | done; `record.sh` (animation-preview skill) still needs a borrow wrapper to record in Live |
| 6 | Memory growth over a long session | Buffers that grow. | Server: the live log ring (300), SSE clients pruned, contexts removed on destroy, one CDP socket. Viewer: log capped (300 lines), history (100), one iframe (inactive tabs unloaded). Chrome's own memory for the live page is the page's. | bounded by design; a multi-hour soak is not done |
| 7 | Security: CDP exposure | While Live is on, `tcp:9222` gives full control of Chrome (every tab, cookies). | adb binds the forward to 127.0.0.1 only (checked: loopback answers, the Wi-Fi address does not). Any app on the phone can still reach loopback, though. The forward exists only while Live is on (removed on leave). The viewer API is loopback-only and its POSTs need `application/json`, which stops cross-origin web pages but not native apps. Stronger: forward to a unix socket in the app's private dir (`adb forward localfilesystem:...` works and is not reachable by other apps), which needs a socket-capable CDP client. | partial; the unix-socket change is open |
| 8 | Test isolation | The e2e test in Stream fallback connects to the real `thor` stream (`ws://127.0.0.1:9223`) briefly. | Harmless (read-only screencast), but the stream URL should be configurable for tests. | open |
| 9 | Heat: Live renders heavy GPU pages at the display's full resolution | Measured 2026-09-19 (60 s runs, `~/.cache/thor-perf/run2`): Canvas Lab title in Live = 58.8% GPU busy, hottest zone reached 91°C by the end; the same page in Stream = 6.3% (the headless page renders at CSS resolution and ships JPEGs). Static page: about 1% (Stream) vs 4% (Live). | Proposed: a thermal guard in the server. When the hottest zone stays above ~80°C, fall back to Stream (same fallback path, with a notice). The A/B harness now aborts a run past 80°C for 5 s. | open, blocks Live-as-default for heavy pages |
